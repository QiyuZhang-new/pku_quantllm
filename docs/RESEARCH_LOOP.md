# 因子研究闭环 V1

## 范围与证据等级

本版实现“生成候选—验证—诊断—生成后继—冻结候选—历史审核—登记生命周期”。
目标是让现有评价与回测体系形成可运行、可追溯的研究流程。

提案器是确定性的规则基线：先按开发结果选择父因子，再根据覆盖、收益或稳定性问题
生成较短/较长窗口与平滑变体。每轮按最新结果重新分配搜索顺序。
可用 `--seeds` 导入外部模型生成的同格式表达式，但本版不会自行调用 LLM API。
规则搜索运行成功不能证明研究方法已经具有递归自我改进的收益优势。

证据等级有明确边界：

- `development_passed`：反复探索的开发期通过，不是独立样本外。
- `frozen_for_review`：公式、方向、协议与产物已冻结，等待一次历史审核。
- `historical_review_passed`：冻结候选在指定历史审核期通过统计和账户门槛。
- `synthetic_control_passed`：合成正对照通过，只验证程序行为。
- `rejected` / `invalid` / `error` / `review_rejected` / `review_error`：保留失败或异常。

当前课程历史已参与过先前研究。因此即使历史审核通过，也不能声称历史从未看过。
本版不会将任何状态自动升级为实盘启用或“已验证独立alpha”。

## 环境与命令

从 QuantLLM 根目录运行，复用 `lesson04/.venv/bin/python`；使用既有
NumPy、pandas、PyArrow，SQLite 为标准库，不需要升级或安装依赖。

```bash
# 合成数据：三轮、最多12个尝试，包含成功和失败；有候选才执行一次审核。
lesson04/.venv/bin/python -m quant_research demo --output research_runs/demo_new

# 真实行情：最多12个候选，两个固定向前开发窗口。默认全证券，非轻量操作。
lesson04/.venv/bin/python -m quant_research discover \
  --protocol configs/research/historical.json \
  --data lesson04/feathers \
  --status lesson04/research/assignment/data/historical_status \
  --seeds configs/research/seeds.json \
  --output research_runs/historical_new

# 查看冻结候选和开发诊断；没有通过者时应保留空结果。
lesson04/.venv/bin/python -m quant_research inspect --output research_runs/historical_new

# 仅当selection.json中有候选时运行。触发后该批次不可再次研究或审核。
lesson04/.venv/bin/python -m quant_research review --output research_runs/historical_new
```

全证券运行会保留多个行情/因子矩阵和账户持仓，可能使用GB级内存并生成较多CSV。
先用 `--symbols 000001.SZ ...` 固定少量证券验证接口；`configs/research/smoke.json`
将批次限制为两轮四个尝试、有效横截面最少30只，其他经济与稳定性门槛保持原设置。
它用于接口验证，不能把固定小证券池的结果当作全市场结论。
实际传入的证券顺序、数据目录及所有输入文件指纹均写入manifest。

`historical.json` 固定：训练截至2022-12-30、验证截至2023-12-29；
第二窗口训练截至2023-12-29、验证截至2024-12-31；历史审核截至2026-09-30。
本地历史状态缓存仅覆盖2022-01-04至2026-09-30，不使用之后的未知状态撮合。
切分不会随新增数据按比例移动；审核要求原输入快照不变。

改变股票池、费用、阈值、时间窗口或搜索预算，应新建协议与输出目录并披露既往暴露。
新建目录不意味着获得新的未见样本。现阶段台账按研究批次保存，尚无跨批次的强制
数据暴露管理；同一历史区间在新批次中重用，仍只能标记为历史探索证据。

## 因子定义

候选为 `FactorSpec` JSON，输出无时区的交易日 × 证券 DataFrame：

```json
{
  "name": "return20_smoothed",
  "expression": {
    "op": "smooth",
    "window": 3,
    "arg": {"op": "return", "window": 20}
  },
  "hypothesis": "检验三日平滑能否提高信号持续性并降低换手",
  "parent_id": null
}
```

可用算子：

| 算子 | 定义 | 信息时点 |
| --- | --- | --- |
| `return` | `close*cumadj` 的过去window日收益 | 截至当日收盘 |
| `volatility` | 过去window个完整日收益的样本标准差 | 截至当日收盘 |
| `market_deviation` | 日收益减当日已知合格证券等权日收益，再计算滚动标准差 | 截至当日收盘；不是OLS特质波动率 |
| `smooth` | 子表达式的滚动均值 | 完整历史窗口 |
| `blend` | 两个子表达式的当日横截面百分位秩均值 | 两项均有效，不填缺失 |

窗口限制2至252，表达式深度至多4。子项组合不会自动搜索正负号，整个因子方向只由
相应训练期均值RankIC确定。数据预处理、排名或因子定义不得利用验证/审核期重新拟合。
表达式不执行任意 Python，不提供文件、网络或评价器修改接口。

ID由规范化表达式和算子版本计算。改名或修改假设不产生新因子；`blend`交换两个子项
也不产生新ID。相同表达式重复提交仍记录尝试并消耗预算。
不同表达式的行为冗余在冻结前以最后开发验证期的平均每日绝对Rank相关检查。
该检查是候选去重，尚未实现行业/规模暴露剥离或组合增量alpha检验。

## 开发验证与交易协议

开发运行给计算器的行情只截至 `development_end`；各窗口再截断到各自验证期末日。
虽然本地Feather读取器需要读取文件后截取，但后续提案器与评价接口不会获得审核期矩阵
或标签。这是程序中的数据边界，不是防止服务器用户直接读取原文件的权限隔离。

因果性检查会对完整开发矩阵、两个历史前缀以及未来价格/成交额/复权因子扰动结果
进行比对。它能捕捉常见负向shift、全样本归一化等泄漏，不是对任意程序的数学证明。

第五讲负责标签与统计：信号t收盘、t+1开盘进入、t+1+h开盘退出，
剔除跨训练边界和期末未到期标签，方向只取训练期。
每轮开始前预登记全部候选；无效和重复候选以p=1参与本轮FDR家族。
HAC与批内FDR均不能消除多轮自适应研究整体的选择偏差。

第四讲负责实际账户路径。适配器使用同一份因子和信号日股票池，按h交易日调仓，
高分组等权；基准为同因子可用股票池的等权账户，费用与成交约束完全相同。
每个窗口独立从现金启动，允许区间前一收盘生成首笔信号，末日尝试开盘清仓。
不再建立无法在区间内完成h日持有的新仓；旧持仓保留至下一实际调仓或末日清仓。
这与“每日都计算一个重叠h日标签”的诊断口径不同，不应混称同一收益序列。

执行协议固定 `standard`：涨停不买、跌停不卖，保留历史状态、T+1、整手、
历史成交额参与率、费用和停牌处理。已存在的 `legacy_reversal` 课程默认值保持不动。
宽表 `eligible/is_st/trade_status/preclose` 可放入行情目录，或用 `--status` 读取既有
逐证券缓存；未知ST/交易状态不进入信号池，成交日状态由账户引擎再次核查。
`is_st` 与 `trade_status` 仅允许0、1、缺失。缺少历史状态默认无法通过账户准入。

评价层默认单边10bp为固定成本情景，往返20bp；账户层按实际成交收取佣金、滑点和
卖出税。两种口径分别在协议中冻结：标签筛选是成本压力诊断，最终经济准入采用账户账本。
现有总收益复权合成持仓、限价近似与无真实盘口冲击的边界继续适用。

候选须在全部开发窗口同时通过第五讲的非test门槛与账户门槛：实际有成交、
基准有成交、总收益为正、相对可执行基准的累计净收益差为正、回撤在预算内、
两账户无陈旧估值且最终均已清仓。单一窗口高分不能补偿其他窗口失败。
开发分数只是最后窗口的净标签超额，用于确定探索与候选优先顺序。

## 封存与历史审核

开发结束后写入 `seal.json`，覆盖全部候选定义、开发因子矩阵、统计、账户及选择产物。
清单自身的哈希保存在SQLite封存事件中。只有全部开发准入通过且未被相关性去重的
有限候选进入一次历史审核。

审核流程先以SQLite事务把状态从 `sealed` 改为 `reviewing`，再验证源码、协议、
输入及产物指纹，最后才计算留出期指标。任何异常都记录为 `review_error` 并关闭机会，
避免在未知数据暴露状态下自动重开。此设计偏保守，进程中断后不会自动重试审核。
若进程被强制终止而停在 `reviewing`，该状态同样拒绝重新审核；保留现场供人工审查。

审核重新计算候选并核对整个开发前缀及训练方向一致，然后执行原第五讲验证/测试准入
和审核期账户回测。结果登记到因子目录，搜索器不再读取该结果以修改本批次候选。
没有开发合格候选时，`review`拒绝读取留出数据；零入库是正常结果。

文件哈希、数据库和状态机用于防止误改、混用和重复运行，不是抵抗拥有本机数据库写权限
用户的安全或审计边界。开发异常与强制中断目前也不支持自动断点续跑，已有目录拒绝覆盖。

## 输出与代码

```text
manifest.json                 数据、源码、版本、股票池、协议及证据等级
protocol.json                 完整展开的冻结协议
registry.sqlite3              因子目录、尝试、父子血缘、生命周期与追加事件
trials/0001/submitted.json    包括无效定义在内的原始提交
trials/0001/factor.json       规范化表达式与ID
trials/0001/development_factor.parquet
trials/0001/fold_01/          统计、日度标签、策略和基准账户明细
trials/0001/summary.json      仅开发反馈，不含审核期指标
selection.json               冻结候选与相关性去重记录
seal.json                    封存清单
review/                      一次历史审核的统计、账户和证据等级
REPORT.md / report.json      可读报告与可机器读取的研究状态
```

| 文件 | 职责 |
| --- | --- |
| `quant_research/contracts.py` | 显式日历窗口、预算、统计与账户协议 |
| `quant_research/factors.py` | 表达式、内容ID、因果检查与反馈提案基线 |
| `quant_research/inputs.py` | 行情/历史状态适配、合成对照与指纹 |
| `quant_research/evaluation.py` | 复用评价器、统一因子策略及账户准入 |
| `quant_research/storage.py` | SQLite台账、事件、目录生命周期与文件证据 |
| `quant_research/pipeline.py` | 有预算的多轮研究、去重封存和一次审核 |
| `quant_research/cli.py` | demo、discover、review、inspect入口 |
| `tests/research/test_research.py` | 跨模块正负对照与回归检查 |
